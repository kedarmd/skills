# Reference-to-product synthesis

An inspiration image or external design is a **research input**, not an implementation blueprint. Do not reproduce its screen structure, branding, assets, typography hierarchy, or signature composition without an explicit product reason and permission to use the assets.

For each reference:

1. **Observe**: identify objective design properties (density, rhythm, contrast, information hierarchy, interaction affordances, navigation structure, use of space, motion language).
2. **Explain**: identify what user problem the reference likely addresses; mark uncertain assumptions rather than stating them as fact.
3. **Research**: examine the actual product's requirements, target users and platform conventions; inspect other comparable patterns when external research tools are available. Record sources and tradeoffs.
4. **Separate**: keep transferable principles apart from brand-specific content, unique arrangements, proprietary visuals or patterns inappropriate for the current product.
5. **Synthesize**: propose an original design direction using the current product's approved system and real use cases. Evaluate alternatives against usability, accessibility, platform constraints and implementation cost.
6. **Check**: compare the resulting screen with the reference. Similarity of principle is acceptable; unintended literal replication is a reason to redesign.

Useful review format: `Reference observation → underlying principle → relevant product need → adaptation → reason not to copy literally`.

Do not let a visual reference silently rewrite approved tokens or component definitions. If adapting the reference truly requires a system change, route it through the formal approval process before using it in a screen.
